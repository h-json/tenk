# Play Console — 앱 콘텐츠 답안지

> **이 문서의 용도**: Play Console → **정책 및 프로그램 → 앱 콘텐츠** 의 각 폼에 무엇을 입력할지,
> 그리고 **그 답이 코드의 어느 사실에 근거하는지**를 한곳에 모은 참조 문서.
> 폼은 콘솔에서 사람이 직접 채운다 — 여기 있는 건 그때 그대로 옮겨 적을 답이다.
>
> **갱신 규칙**: 수집 항목·권한·SDK·연령 정책이 바뀌면 **이 문서 + [privacy.html](../tenk-backend/src/main/resources/static/privacy.html) + Play Console 폼 3곳을 같이** 갱신할 것.
> 셋 중 하나만 바뀌면 심사에서 불일치로 걸린다. 진행 상태는 [handoff.md](handoff.md).

작성 기준일: 2026-07-20 · 대상: applicationId `com.hjson.tenk_app` (표시 이름 **Tenk**)

## 2. 앱 액세스 권한 (App access)

**"앱의 전체 또는 일부에 액세스 권한이 제한됩니다"** 를 선택하고 심사자용 접근 방법을 제공해야 한다.
카카오 로그인 전용이라 심사자가 그냥은 못 들어간다.

> ✅ **확정 — 데모 카카오 계정 방식** (2026-07-25 테스터 로그인 회의 결정, [decisions.md](decisions.md) "테스터 로그인 회의").
> 앱 내 우회 테스트 로그인은 **완전히 제거**했고(코드에 흔적 없음), 심사자는 데모 카카오 계정으로 순정 앱에
> 로그인한다. 이메일 전용 카카오계정(전화번호·본인인증 없이 `accounts.kakao.com` 가입)이 데모 계정으로
> 동작함을 에뮬레이터에서 확인했다.

**답안 — 데모 카카오 계정 로그인**:

```
로그인 필요: 예
사용자 이름(아이디): <데모 카카오계정 이메일>
비밀번호: <데모 카카오계정 비밀번호>
안내:
1. 앱 실행 후 '카카오로 로그인' 을 누릅니다.
2. 위 이메일/비밀번호로 카카오 계정에 로그인합니다.
3. 로그인 후 모든 기능을 사용할 수 있습니다. (별도 결제·유료 구간 없음)
```

**준비물·주의**:
- **데모 카카오 계정을 1개 생성**해 위 칸에 아이디/비밀번호를 적는다. 아직 미생성 → 제출 전 실행 항목([handoff.md](handoff.md) §0).
- **데모 계정은 영구 유지** — Play 는 업데이트마다 바이너리를 재심사하므로 첫 심사만이 아니다.
- 새 기기(심사자 단말) 로그인 시 카카오가 추가 인증을 띄울 수 있다. 전화번호 없는 이메일 전용 계정이면 이메일
  인증코드로 나올 가능성이 높지만 카카오 정책이라 100% 보장은 아니다 — **제출 전 한 번 새 기기에서 재현**해
  추가 인증이 안 뜨거나 이메일 코드로 통과되는지 확인할 것. 뜨면 Review Notes 에 대응법을 적는다.
- 프로덕션 AAB 는 아무 특별 dart-define 없이 빌드하면 된다(테스트 로그인은 코드에서 제거됨). 서버도 테스트
  로그인 엔드포인트가 없다. **내부 테스터의 시딩**은 실제 카카오 계정을 DB 에서 `role='TESTER'` 로 승격해 쓴다
  (심사자 데모 계정은 절대 승격하지 말 것 — 승격하면 '내 정보'에 테스트 데이터 재생성 버튼이 노출된다).

## 5. 타겟층 및 콘텐츠

| 필드 | 답 |
|---|---|
| 타겟 연령대 | **13~15세, 16~17세, 18세 이상** |
| 스토어 등록정보가 아동의 관심을 끄나요? | **아니요** (그래픽·문구 모두 성인/청소년 대상 톤) |

**그 대가 — 가족 정책(Families Policy) 적용**. 요건별 현황:

| 가족 정책 요건 | Tenk 현황 |
|---|---|
| 아동에게 노출되는 광고는 인증 광고 SDK 만 사용 | **해당 없음** — 광고 자체가 없음 |
| 중립적 연령 심사(neutral age screen) | **구현함** — [AgeGateScreen](../tenk_app/lib/presentation/legal/age_gate_screen.dart) |
| 연령에 적합한 콘텐츠 | **충족** — 개인 지출 기록 앱, 부적절 콘텐츠 없음 |
| 개인정보처리방침 게시 | **충족** (§1) |

**연령 심사의 중립성 설계** (정책 위반 소지를 없애려고 일부러 이렇게 했다 — 바꾸지 말 것):
- 입력 **전에 컷오프(만 14세)를 알려주지 않는다.** 먼저 알려주면 통과하는 값을 역산해 넣도록 유도하는 셈.
- 기본값·초기 선택값이 없다 (DatePicker 대신 빈 입력칸 3개).
- 판정은 서버가 한다. 만 14세 미만이면 **계정과 수집된 정보를 즉시 파기**하고 재시도 없이 로그아웃.

## 6. 데이터 안전 (Data safety)

### 6-1. 개요 질문

| 질문 | 답 |
|---|---|
| 앱이 사용자 데이터를 수집하거나 공유하나요? | **예 (수집함 / 공유 안 함)** |
| 전송 중 데이터가 암호화되나요? | **예** — 전 구간 HTTPS |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **예** — 앱 내 탈퇴 + 웹 요청 |
| 데이터 삭제 URL | `https://tenk.hjson248.com/delete-account.html` |
| 독립적인 보안 검토를 거쳤나요? | **아니요** |

> **"공유"의 정의 주의**: Play 에서 공유 = *제3자에게 데이터를 전송*. 카카오 로그인은 우리가 카카오로부터
> 정보를 **받는** 것이라 공유가 아니다. 영상·기록도 자체 서버에만 저장된다 → **전 항목 공유 아니요**.

### 6-2. 수집 항목별 답안

모든 항목 공통: **공유 = 아니요**, **수집 = 예**, **처리 방식 = 데이터가 서버로 전송되어 저장됨**(임시 처리 아님).

| Play 데이터 유형 | 실제 항목 | 필수/선택 | 수집 목적 |
|---|---|---|---|
| 개인 정보 → **이름** | 닉네임 | 필수 | 앱 기능, 계정 관리 |
| 개인 정보 → **이메일 주소** | 카카오 계정 이메일 | 필수 | 앱 기능, 계정 관리 |
| 개인 정보 → **사용자 ID** | 카카오 회원번호 | 필수 | 앱 기능, 계정 관리 |
| 개인 정보 → **기타 정보** | 생년월일 | 필수 | 앱 기능(이용 가능 연령 확인) |
| 개인 정보 → **기타 정보** | 성별 | **선택** | **분석** (이용자 통계) |
| 금융 정보 → **기타 금융 정보** | 이용자가 입력한 지출 금액·카테고리·내용·한 줄 평 | 선택 | 앱 기능 |
| 사진 및 동영상 → **동영상** | 이용자가 촬영해 첨부한 2초 영상 | 선택 | 앱 기능 |

**"선택"으로 답하는 근거**: 지출 기록과 영상은 사용자가 입력·촬영을 선택했을 때만 수집된다.
로그인만 하고 아무것도 기록하지 않아도 앱은 동작한다. **성별**은 가입 흐름에 없고 '내 정보' 화면에서
본인이 원할 때만 입력하며, 언제든 '입력 안 함'으로 되돌려 삭제할 수 있다 — 기능은 이 값을 전혀 쓰지 않는다.

> **성별만 목적이 '분석'인 이유**: 나머지 항목은 서비스 기능 제공에 필요하지만 성별은 이용자 통계 용도뿐이다.
> 목적을 '앱 기능'으로 적으면 실제 동작과 어긋난다. 이 항목을 **필수로 바꾸거나 가입 흐름으로 옮기면
> 개인정보 최소수집 원칙에 걸리므로** 선택·사후 입력 구조를 유지할 것.

### 6-3. 수집하지 않는다고 답할 항목 (자주 헷갈리는 것들)

| 항목 | 답 | 근거 |
|---|---|---|
| 오디오 → 음성 녹음, 음악, 기타 오디오 | **미수집** | `enableAudio: false` — 영상 트랙에 오디오가 들어가지 않는다. 매니페스트에 `RECORD_AUDIO` 가 선언돼 있지만 **권한 선언 ≠ 수집**이며 Play 폼은 실제 수집 여부를 묻는다 |
| 위치 | 미수집 | 위치 권한·API 미사용 |
| 연락처 / 캘린더 / 문자 / 통화 기록 | 미수집 | 관련 권한·API 없음 |
| 기기 또는 기타 ID (광고 ID 포함) | 미수집 | 광고·애널리틱스 SDK 없음 |
| 앱 활동 (검색어, 조회 항목 등) | 미수집 | 행동 로깅 SDK 없음 |
| 앱 정보 및 성능 (크래시 로그, 진단) | 미수집 | 크래시 리포팅 SDK 없음 |
| 결제 정보 / 구매 내역 | 미수집 | 인앱 결제 없음 |

> ⚠️ **판단이 갈릴 수 있는 한 지점 — 서버 접속 로그.** privacy.html §1 은 "서비스 이용 과정에서 생성되는
> 접속 로그 및 오류 기록"을 명시하고 있다. 이는 웹서버 운영 로그이고 사용자 계정 데이터로 DB 에 저장되지
> 않으므로 위 표대로 **"앱 정보 및 성능: 미수집"** 으로 답하는 게 통상적이다. 추후 크래시 리포팅
> SDK(Firebase Crashlytics 등)를 도입하면 **그 즉시 "크래시 로그: 수집"으로 바꿔야 한다.**

## 8. 제출 전 체크리스트

- [ ] 개인정보처리방침 URL 접속 확인 (`/privacy.html`)
- [ ] 계정 삭제 안내 URL 접속 확인 (`/delete-account.html`) ← **이번에 신설, 배포 필요**
- [ ] 이용약관 URL 접속 확인 (`/terms.html`)
- [ ] 앱 액세스 권한: **데모 카카오 계정** 생성 + **새 기기에서 로그인 재현**(추가 인증 안 뜨는지) 확인 (§2)
